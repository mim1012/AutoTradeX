✅ 총평

아키텍처( WPF + MVVM / UI 스레드에 COM 고정 / 조건엔진 분리 ) 방향은 매우 적절함.

다만 키움 OpenAPI+ 해외주식 영역의 TR/주문 파라미터에서 사실관계와 매핑이 일부 불명확함.
특히 LOC 주문 처리와 해외주식용 TR 코드는 정확 값 재확인이 필요함.

🔧 수정이 꼭 필요한 포인트 (하이-프라이오리티)
1) SendOrder 파라미터 맵핑

TRD에 “nOrderType: 6 (LOC)”로 표기했는데, 잘못이야.
nOrderType은 **주문 성격(매수/매도/정정/취소)**을 의미하고, OpenAPI 기본 스펙은 다음과 같아:

1: 매수, 2: 매도, 3: 매수취소, 4: 매도취소, 5: 매수정정, 6: 매도정정 
위키독스
+1

LOC는 ‘호가구분(또는 해외주문 전용 필드)’로 지정하는 게 맞음.
즉, nOrderType=1(매수) + sHogaGb=LOC에 해당하는 코드 형태가 되어야 한다.
(국내는 ‘00=지정가, 03=시장가’처럼 표준이 공개돼 있으나, 해외주식의 LOC 호가코드는 별도 표를 확인해야 함. 이 값은 키움 해외주식 주문 가이드/개발가이드에서 확인 필요) 
위키독스

또한 키움 고객센터 가이드에서 LOC/MOC는 마감 10분 전 이후 거부/미체결 가능성 언급됨 → 종가 직전 안전 버퍼/리트라이 정책 반영 권장. 
키움증권

권장 수정 (문구)
- nOrderType: 1 (매수)
- sHogaGb: 해외주식 LOC 코드(키움 해외주문 호가구분표 참조)  ← TR 표로 치환
- sPrice: "0" (LOC가 가격 미입력 방식인지, 또는 지정가+조건 조합인지는 가이드 문서로 최종 확인)

2) 해외주식 TR 코드 정확성

TRD에 기재한 opw20004, opw20009, opw20012는 국내/해외/파생 영역이 혼재되어 보임.
예를 들어 해외파생(OpenAPI-W)은 별도 가이드·TR 세트가 있고(SendOrder 등 메소드셋은 유사), 해외선물 쪽은 opw3xxxx 계열이 존재. 반면 해외주식의 과거시세·계좌·주문가능금액 TR은 별도 표를 확인해야 한다. 현재 문서의 TR 배치는 신뢰도 낮음. 
키움증권 다운로드
+1

제안: “TR 명세 테이블”을 별도 부록으로 분리하고, 실제 가이드 PDF/HTS 도움말 기준으로 정확 코드/필드명을 채워 넣자. (예: 계좌·예수금·주문가능금액, 기간별 주/일봉, 해외장 시간 조회 등)

체크리스트

 해외주식 기간별 주가(TR) 정확 코드 확인 및 필드 매핑

 해외주식 주문가능금액/총평가금액(TR) 정확 코드 확인

 잔고상세(TR) 확인 (보유 여부 판단용)

 거래소/마감시간 조회(TR 또는 세션 이벤트) 확인

참고: OpenAPI+ 기본 메소드 셋(로그인/조회/주문/실시간 콜백)은 동일하지만, TR ID와 필드셋은 도메인별로 다름. 공식 Dev Guide/HTS 도움말 표를 근거로 다시 채워야 함. 
키움증권 다운로드

3) 서머타임/마감시각 판정

“opw20012(해외증시 시간외시간)”로 서머타임 자동 반영을 언급했지만, 해당 TR의 정확 명세는 문헌에서 확인 불가.

대안:

키움 제공 해외장 세션/마감 이벤트/정보 TR을 정확히 확인·사용

보조로 거래소 캘린더(서머타임/조기폐장/휴장일) 내장 테이블(정적) + 실시간 세션 정보의 이중화 판정

마감 10~12분 전 LOC 유효성 체크 + 5분/2분/30초 재확인 단계 도입 (거부/미체결 리스크 완화)

LOC/MOC 10분 규정에 대한 사용자 고지를 UI에도 표시하자. 
키움증권

👍 타당하고 좋은 부분 (그대로 유지)

UI 스레드에 COM(OCX) 고정, Worker는 계산 전용 → 옳다. WPF Dispatcher로 UI 스레드 호출 위임 구조 OK.

조건엔진 인터페이스 분리(ICondition… Evaluate()) → 확장성과 테스트 용이성 높음.

Serilog/NLog 채택, 데이터 바인딩 기반 상태표시 → 운영 가시성 확보에 적합.

요청 레이트 제한(조회 200ms 간격) → 보수적으로는 Queue 기반 Throttling으로 강제화 추천. 
위키독스

📦 세부 개선 제안 (미디엄-프라이오리티)
A) 주문 “한 번만 실행” 보장

종가 시각 직전 조건 True 플리커링 방지:

“직전 60초 평균 True” or “마감 T-60s, T-30s, T-5s 연속 True” 같은 안정 필터 추가 추천.

중복 주문 록(lock): 주문번호 수신 전까지 재호출 금지.

B) 실패/예외 전략

주문 거절/미체결 시:

원인 로그(호가코드/시간제한/잔고/체결거래량 부족)

정책: 즉시 포기 / 지정가 대체 / 다음 장으로 이월 (옵션화)

세션 끊김: OnEventConnect/GetConnectState() 감시 + 재로그인 백오프(예: 5s→15s→60s)

C) 데이터 캐싱

조건에 주봉이 포함되므로 주봉 재계산(주간 OHLC 집계) 로직 준비(일봉 합성 or TR 조회).

거래대금 단위(백만/천/통화) 통일: UI에 단위 표기 강제.

D) 로깅/감사 추적

주문 Life-cycle: 요청 → 접수 → 체결/부분체결 → 미체결 종료

OnReceiveTrData(주문 결과)와 OnReceiveChejanData(체결/잔고) 둘 다 저장.
