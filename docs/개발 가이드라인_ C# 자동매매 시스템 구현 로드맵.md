# 개발 가이드라인: C# 자동매매 시스템 구현 로드맵

**프로젝트명**: 한국투자증권 API 기반 미국주식 자동매매 시스템
**버전**: 1.0
**작성일**: 2025년 11월 10일

---

## 1. 개요

본 문서는 PRD v3.0과 TRD v2.0을 기반으로, C# 자동매매 시스템을 단계별로 구현하기 위한 구체적인 개발 로드맵과 가이드라인을 제공합니다. 각 단계는 독립적으로 테스트 가능한 작은 단위로 구성되어 있습니다.

---

## 2. 개발 환경 설정 (Phase 1)

**목표**: 프로젝트 개발에 필요한 기본 환경을 구축합니다.

- **[ ] 1. 프로젝트 생성**: Visual Studio 2022에서 다음 두 개의 프로젝트를 생성합니다.
  - `AutoTrader.Worker` (.NET Worker Service)
  - `AutoTrader.UI` (WPF Application)
- **[ ] 2. NuGet 패키지 설치**: TRD v2.0에 명시된 주요 NuGet 패키지를 각 프로젝트에 설치합니다.
  - `Microsoft.Extensions.Hosting`
  - `CommunityToolkit.Mvvm`
  - `Serilog`
  - `Newtonsoft.Json`
  - `Polly`
- **[ ] 3. 폴더 구조 생성**: TRD v2.0의 아키텍처에 따라 각 프로젝트에 필요한 폴더(Services, ViewModels 등)를 생성합니다.
- **[ ] 4. 소스 코드 관리**: GitHub 리포지토리를 생성하고 초기 프로젝트 구조를 커밋합니다.

---

## 3. API 연동 및 인증 (Phase 2)

**목표**: 한국투자증권 API와 통신하기 위한 기본 클라이언트를 구현합니다.

- **[ ] 1. API 데이터 모델(DTO) 생성**: Claude 스킬을 활용하여 API 응답을 담을 C# DTO 클래스들을 생성합니다. (`KisApiResult.cs`, `StockRank.cs` 등)
- **[ ] 2. 인증 서비스 구현**: `KisAuthService.cs`를 생성하고 다음 기능을 구현합니다.
  - REST API용 Access Token 발급 및 자동 갱신 (1시간마다)
  - WebSocket용 접속키(approval_key) 발급
- **[ ] 3. API 클라이언트 구현**: `KisApiClient.cs`를 생성하고, `HttpClient`와 `Polly`를 사용하여 API 호출 및 재시도 로직을 구현합니다.
- **[ ] 4. 단위 테스트**: 인증 및 API 호출이 정상적으로 동작하는지 단위 테스트를 작성하여 검증합니다.

---

## 4. 핵심 기능 구현 (Phase 3)

**목표**: 프로젝트의 핵심 비즈니스 로직을 구현합니다.

- **[ ] 1. 거래대금 순위 조회**: `SchedulerService.cs`에서 15분마다 `KisApiClient`를 호출하여 거래대금 상위 300종목을 조회하는 로직을 구현합니다.
  - **주의**: 모의투자에서는 지원되지 않으므로, 초기에는 Mock 데이터를 사용합니다.
- **[ ] 2. WebSocket 시세 수신**: `WebSocketManager.cs`를 구현합니다.
  - 300개 종목을 8개 세션으로 나누어 실시간 시세를 구독합니다.
  - 수신된 데이터를 파싱하여 `OnDataReceived` 이벤트를 발생시킵니다.
- **[ ] 3. 조건식 평가 로직**: `ConditionEvaluator.cs`를 생성하고, 실시간 데이터와 사전 조회된 데이터를 기반으로 사용자 정의 조건식을 평가하는 로직을 구현합니다.
- **[ ] 4. 주문 실행 로직**: `OrderExecutor.cs`를 생성하고, 장마감 10분 전에 최종 후보를 선정하여 LOC 주문을 실행하는 로직을 구현합니다.

---

## 5. UI 개발 (Phase 4)

**목표**: 시스템 상태를 모니터링하고 설정을 변경할 수 있는 WPF UI를 개발합니다.

- **[ ] 1. ViewModel 구현**: Claude 스킬을 활용하여 `MainViewModel`, `DashboardViewModel`, `SettingsViewModel` 등 MVVM 패턴에 따른 ViewModel 클래스들을 구현합니다.
- **[ ] 2. View 구현**: XAML을 사용하여 각 ViewModel에 맞는 View(Window, UserControl)를 디자인합니다.
  - 데이터 바인딩을 사용하여 View와 ViewModel을 연결합니다.
- **[ ] 3. 실시간 데이터 연동**: 백그라운드 서비스에서 발생한 이벤트(예: 계좌 상태 변경, 로그 추가)를 `Dispatcher.Invoke`를 통해 UI에 안전하게 반영합니다.

---

## 6. 통합 및 테스트 (Phase 5)

**목표**: 모든 컴포넌트를 통합하고, 실제 환경에서 시스템의 안정성을 검증합니다.

- **[ ] 1. Worker Service 통합**: 구현된 모든 서비스(`SchedulerService`, `WebSocketManager` 등)를 `AutoTrader.Worker`의 `Program.cs`에 등록합니다.
- **[ ] 2. 통합 테스트 (모의투자)**: 모의투자 계좌를 사용하여 전체 시스템의 데이터 흐름과 주문 로직을 테스트합니다.
- **[ ] 3. 통합 테스트 (실전)**: 실전 계좌를 사용하여 다음을 순서대로 테스트합니다.
  - **조회/시세**: 거래대금 순위 조회 및 실시간 시세 수신 기능 검증
  - **소액 주문**: 실제 소액으로 LOC 주문이 정상적으로 실행되고 체결되는지 최종 검증
- **[ ] 4. 배포**: 테스트가 완료된 애플리케이션을 VPS 서버에 배포하고, Windows Service로 등록하여 24시간 자동 실행되도록 설정합니다.

---

## 7. 코드 품질 가이드라인

- **네이밍 컨벤션**: Microsoft C# 코딩 규칙을 준수합니다. (PascalCase, camelCase)
- **주석**: 복잡한 로직이나 비즈니스 규칙에는 반드시 주석을 추가하여 다른 개발자가 쉽게 이해할 수 있도록 합니다.
- **에러 처리**: 모든 외부 API 호출 및 파일 I/O 작업에는 `try-catch` 블록을 사용하여 예외를 처리하고, 에러 발생 시 로그를 기록합니다.
- **SOLID 원칙**: 단일 책임 원칙(SRP), 개방-폐쇄 원칙(OCP) 등 SOLID 원칙을 최대한 준수하여 유연하고 확장 가능한 코드를 작성합니다.
- **코드 리뷰**: 주요 기능 구현 후에는 동료 개발자와 코드 리뷰를 진행하여 잠재적인 문제를 사전에 발견하고 코드 품질을 개선합니다.
