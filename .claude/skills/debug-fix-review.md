# debug-fix-review

WPF/C# 애플리케이션의 오류를 디버깅하고, 자동으로 수정하며, 변경사항을 리뷰하는 스킬입니다.

## 작업 흐름

### 1. 오류 수집 및 분석
- 실행 중인 애플리케이션의 오류 메시지 확인
- 빌드 로그에서 컴파일 오류 추출
- 런타임 예외 및 스택 트레이스 분석
- 오류 패턴 식별 (STA 스레드, null reference, binding 오류 등)

### 2. 자동 수정
- 오류 유형에 따른 수정 전략 적용
- 관련 파일 읽기 및 문제 코드 식별
- 코드 수정 및 검증
- 빌드 및 실행으로 수정 확인

### 3. 변경사항 리뷰
- 수정된 파일 목록 작성
- 변경 전/후 비교
- 수정 이유 및 영향도 분석
- 추가 개선 사항 제안

## 실행 방법

이 스킬은 다음과 같이 사용됩니다:

1. **자동 실행**: 오류 발생 시 자동으로 디버깅 시작
2. **수동 실행**: 사용자가 명시적으로 요청

## 지원하는 오류 유형

### WPF 관련 오류
- STA 스레드 오류
- DataContext 바인딩 오류
- Window Owner 설정 오류
- XAML 파싱 오류
- Resource not found 오류

### C# 런타임 오류
- NullReferenceException
- InvalidOperationException
- ArgumentException
- TaskCanceledException

### 빌드 오류
- 컴파일 오류
- 참조 누락
- 타입 불일치
- 네임스페이스 오류

## 수정 전략

### 1. STA 스레드 오류
```yaml
증상: "호출 스레드가 필요하므로 해당 스레드는 STA여야합니다"
원인: UI 컴포넌트를 잘못된 스레드에서 생성
수정:
  - Application.Current.Dispatcher.Invoke 사용
  - Window Owner를 올바르게 설정
  - async/await 패턴 확인
```

### 2. Null Reference 오류
```yaml
증상: "개체 참조가 개체의 인스턴스로 설정되지 않았습니다"
원인: null 객체 접근
수정:
  - null 체크 추가
  - nullable 타입 사용
  - 기본값 제공
  - 초기화 순서 확인
```

### 3. Binding 오류
```yaml
증상: "BindingExpression path error"
원인: DataContext 또는 Property 경로 오류
수정:
  - DataContext 설정 확인
  - Property 이름 확인
  - RelativeSource 또는 ElementName 수정
  - INotifyPropertyChanged 구현 확인
```

## 사용 예시

Skill: debug-fix-review 자동 실행
1. 오류 수집: STA 스레드 오류 확인
2. 원인 분석: Window Owner 설정 문제

4. 검증: 빌드 및 실행 테스트

```

4. 재빌드 및 검증
5. 수정 리포트 제공
```

## 설정

### 자동 실행 조건
- 오류 메시지가 포함된 사용자 입력
- 빌드 실패 감지
- 런타임 예외 발생

### 수동 실행
사용자가 명시적으로 요청:
- "디버깅해줘"
- "오류 수정해줘"
- "코드 리뷰해줘"

## 제한사항

1. **복잡한 비즈니스 로직 오류**: 도메인 지식이 필요한 오류는 수동 개입 필요
2. **외부 의존성 오류**: 네트워크, 데이터베이스 등 외부 시스템 문제는 수정 불가
3. **설계 문제**: 아키텍처 수준의 문제는 수정 제안만 제공
